# FargoVPN 4.4.3

## Исправление дублей во вкладке «Сообщения»

- Исправлена выборка списка диалогов: группировка выполняется по уникальному `tg_id`, а не по историческим значениям `username`.
- Смена username больше не создаёт второй чат одного и того же Telegram-пользователя.
- Добавлен regression-тест на повторяющиеся события и смену username.
- Схема БД и существующие данные автоматически не изменяются.

## Исправление резервного копирования

- Исправлена подготовка age recipient: пустой `BACKUP_AGE_RECIPIENT` больше не считается валидной настройкой.
- При необходимости backup worker использует локальный age-ключ для определения recipient без хранения приватного ключа в архиве.
- Ошибка загрузки на Яндекс.Диск больше не блокирует отправку того же архива в Telegram.
- Ошибка Telegram больше не блокирует независимую загрузку на Яндекс.Диск.
- Результаты обоих каналов доставки фиксируются независимо, поэтому неуспешный канал может быть отправлен на повторную попытку.
- Сохранено согласованное создание SQLite snapshot для БД 3x-ui и отправка большого Telegram-архива частями с запасом относительно лимита Bot API.

## Проверка

- Targeted regression tests: passed.
- Python syntax/compile checks: passed.
- Рабочие базы, подписки, оплаты и API 3x-ui не изменялись.


### Яндекс.Диск

Выгрузка резервных копий выполняется через системный `davfs2`: учётные данные записываются в `/etc/davfs2/secrets`, Диск монтируется как `https://webdav.yandex.ru:443` в `/media/YandexDisk`, после чего архив копируется в смонтированную файловую систему. Прямая HTTP-загрузка через `httpx` для Яндекс.Диска не используется.
