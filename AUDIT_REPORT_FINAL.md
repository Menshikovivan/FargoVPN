# FargoVPN 5.1.21 — итог аудита и Linux-приемки

Дата завершения: 17 октября 2026 года. Объект: предоставленный FargoVPN 5.1.20 и исправленная локальная сборка 5.1.21.

**Результат: сборка подготовлена для установки и обновления.** На изолированной Linux VM подтверждены чистая установка, обновление 5.1.20 → 5.1.21, аварийный откат после фактического изменения БД и работа через Nginx L4/L7. Предыдущий архив 5.1.21-audit.1 заменен окончательным 5.1.21_FULL; использовать следует новый файл.

Это локальная исправленная сборка исходного архива, не объявление официального GitHub-релиза издателя. На пользовательский сервер ничего не устанавливалось. Проверки не заменяют независимую резервную копию конкретного сервера перед обновлением.

## Стенд и совместимость с базовым скриптом

На Windows-хосте в рабочую папку распакован QEMU; системная установка гипервизора и изменение Windows-компонентов не выполнялись. Создана Debian 12 VM с аппаратным WHPX, 2 vCPU, 4 GiB RAM и отдельным 16 GiB диском. Образ Debian и QEMU сверены с опубликованными SHA-512. Использованы настоящий systemd, PostgreSQL 15, Nginx Mainline 1.31.7, Python 3.11, Node.js, Chromium и Playwright. SSH/HTTPS доступны были только через localhost. После завершения активного процесса VM нет, диск сохранен для воспроизведения.

Источник базового шлюза: https://github.com/Itman75/Nginx-L4-Stream-Router-Mask-for-3x-ui , commit **382038b5409955c87a010e92c290c05d7f88d2a0**. Его mainline Nginx-шаблоны извлечены без исполнения установочных шагов. В VM развернуты реальные TCP443 L4, SNI, PROXY protocol, SSL Unix L7 и fallback9443, HTTP/2 и отдельный URI FargoVPN. Для доменов использован локальный сертификат с SAN; Chromium отдельно доверял тестовому CA без обхода TLS.

Сохранение маршрутов маскировки, панели, подписок, xHTTP и DataSphere проверено на контролируемых backend endpoints; xHTTP backend действительно использовал HTTP/2. Затем вместо Fargo stub проверено настоящее установленное приложение. Полный базовый скрипт не запускался: его SSH/UFW/ACME/AWG/DKMS и публичный DNS не проверены и не изменялись. Это проверка точной Nginx-топологии и надстройки FargoVPN, не сертификация всего базового установщика.

Отдельно установлен в собственный каталог официальный 3x-ui **v3.10.2**, Xray 26.10.10. Архив release сверялся с digest официального GitHub API. Рабочее приложение не переводилось на тестовый 3x-ui; API adapter проверялся с отдельной конфигурацией и SQLite. Все тестовые процессы 3x-ui/Xray остановлены после проверки принадлежности.

## Исправления в 5.1.21

1. Исправлены незакрытая кавычка CSS/Telegram SDK и незавершенный JavaScript кабинета; восстановлены копирование подписки/приглашения и обработчик выхода.
2. Страница подключения корректно учитывает WEB_PUBLIC_PREFIX.
3. Настройки: связаны 67 подписей полей, добавлены tablist/tabpanel и клавиши Arrow/Home/End.
4. Nginx guard отдает приоритет явно выбранному домену, исключает reject-handshake host; HSTS сохраняется и на ошибках gateway, без дублирования CSP/HSTS.
5. Uvicorn на UDS и systemd-fd принимает HTTPS/IP от доверенного Unix-прокси. Ранее реальные тесты давали HTTP/client=None. Доверие ограничено Unix listener и правами socket; Nginx заменяет клиентский X-Forwarded-For фактическим адресом из L4, не дописывает недоверенный адрес браузера.
6. Лимиты restore исправлены с ошибочных минимум 1 TiB на объявленные 4 GiB суммарно и 512 MiB/файл; ограничение числа tar members применяется во время чтения. Введены бюджеты AST/COPY/строк.
7. Смена логина/пароля отзывает старые auth sessions. После обновления нужен повторный вход.
8. Автооткат сохраняет .venv и согласованный PostgreSQL public snapshot. Восстановление БД выполняется одной транзакцией; частичный неуспешный restore не оставляет пустую БД.
9. Перед snapshot и rollback останавливаются sockets/timers, web/bot/background writers, включая legacy units и broadcast instances. Проверяется, что они остановлены; при невозможности безопасной остановки откат не меняет файлы/данные.
10. Helper отката сохраняется вне TARGET, чтобы самообновление не удаляло собственный инструмент восстановления. Промежуточные backup-файлы приватны с момента создания; checksum и ownership проверяются.
11. PostgreSQL bootstrap больше не меняет пароль общей роли или владельца чужой БД: новая установка выбирает отдельные DB/role. systemctl reset-failed ограничен управляемыми Fargo units.
12. Restore больше не исполняет SQL/psql команды из backup. Импортируются COPY-данные в доверенную текущую схему; затем проверяются индексы/FK. SQLite импортирует строки в копию действующей схемы, не архивные DDL/triggers, и проверяет foreign_key_check до замены.
13. Архивный код, systemd, .env, VAPID и настройки запуска сервисов не устанавливаются при restore. Fargo config — только разрешенные literal бизнес-настройки. Обновлены тексты UI/CLI и документация.
14. Согласованы VERSION, static/VERSION и PANEL_BUILD_VERSION; устранен ложный баннер версии. Unix-переносы и соответствие клиентской версии проверяются регрессиями.

## Реальные установочные проверки

**Чистая 5.1.20 → успешное обновление 5.1.21.** Исходный установщик выполнен интерактивным драйвером с вымышленными локальными реквизитами. После создания корректного Nginx fixture установился с exit0. Далее настоящий новый installer --update-existing завершился exit0; версия5.1.21, web/socket/nginx active, timers active.

**Forced failure после миграции → успешный возврат.** В отдельной копии установочного пакета, никогда не включенной в поставку, init_db после обычной миграции удалял контрольную строку, создавал новую таблицу и выбрасывал специальный RuntimeError. Проверено наличие именно этого RuntimeError — ранний отказ не считается тестом отката. Результат: exit1 ожидаем; версия вернулась5.1.20, строка с Unicode восстановлена, новая таблица отсутствует, .venv существует, web/socket active, /health200. После этого выполнено нормальное обновление. Доказательства: linux-forced-failure-results.json, linux-forced-failure-install.txt, linux-normal-upgrade-detailed.txt.

**Чистая 5.1.21 из tar.** Предыдущая установка сохранена отдельно, старые DB/role оставлены. Новый установщик из упакованного дерева завершился exit0, создал другую DB/role. Старые credentials продолжают работать и контрольная строка сохранена; в новой БД нет старой контрольной таблицы. Доказательства: linux-clean-isolation.txt, linux-candidate-clean-install-detailed.txt.

Первый тестовый запуск harness имел ошибки собственных HTTP/2 assertions и не содержал nginx user; они исправлены до успешной приемки и не объявлялись дефектами FargoVPN. Проверка также обнаружила Windows CRLF в промежуточном VERSION: итоговая сборка нормализована, регрессия проверяет LF. Промежуточный audit.1 больше не предназначен для установки.

## Изменение контракта восстановления

Режим all/full восстанавливает данные FargoVPN/3x-ui и разрешенные бизнес-настройки в установленную текущую схему. Произвольный backup теперь не является способом вернуть исполняемые файлы/units/env/секреты/настройки запуска. Записи VPN inbound и клиентов3x-ui являются данными и могут измениться при таком восстановлении; оператор должен выбирать нужный backup. Тип SQLite/PostgreSQL3xui должен совпадать, несовместимая схема отклоняется. При нестандартных FK users-only намеренно может отказать, сохраняя live-данные.

Для полного восстановления иной версии сначала отдельно установите доверенный пакет этой версии и настройте доступы, затем восстанавливайте совместимые данные. Индивидуальный logout не добавляет серверный реестр отзыва cookie; смена credentials отзывает предыдущие сессии.
