# FargoVPN 4.4.1

## Массовая рассылка

Исправлена ошибка `Недействительный CSRF-токен` при запуске массовой рассылки. Страница рассылки использует отдельный XHR для прогресса загрузки вложения; теперь этот XHR передаёт тот же session CSRF-токен, который сервер проверяет для всех POST-запросов панели. Защита CSRF не отключалась.

## Резервное копирование

Плановый бэкап продолжает запускаться через `vpn-service-backup.timer` с worker `backup.py --scheduled`. Кнопка `💾 Бэкап` в Telegram-админке запускает тот же worker в режиме `--force`, поэтому ручной запуск и веб-панель используют один и тот же путь создания/доставки.

## Резервное копирование: hotfix 4.4.1

- 3x-ui теперь автоматически резервируется как PostgreSQL dump при настроенном `XUI_DB_DSN` или как согласованный read-only SQLite snapshot `/etc/x-ui/x-ui.db` для legacy-установок.
- SQLite snapshot проверяется через `PRAGMA integrity_check`; рабочая БД не изменяется.
- WebDAV использует прямой потоковый `PUT` в конечный файл с последующей проверкой размера; добавлены понятные сообщения для HTTP 401/403/404/409/507.
- Ошибка создания архива теперь записывается в `backup_runs`, даже если архив не успел создаться.
- После ручного или планового запуска администратору отправляется итоговый статус Telegram с результатами Telegram/Яндекс.Диска и очередью повторов.
- Telegram сохраняет ограничение по частям до 45 MB, чтобы не пересекать лимит Bot API.

## Проверка релиза

- 3 version markers синхронизированы на `4.4.1`.
- Регрессионные контракты backup/WebDAV проходят.
