# FargoVPN 4.7.5

## Исправлено

- Исправлен HTTP 500 в веб-панели при отправке сообщения пользователю: успешная доставка в Telegram больше не превращается в ошибку из-за проблем вспомогательного `message_log`, журнала сообщений или подготовки JSON-ответа.
- Отправка фото и видео из панели теперь также не зависит от успешной записи журнала.
- Проверены и исправлены аналогичные post-success сценарии в пользователях, подписках, комментариях, Telegram-привязках, удалении, обновлениях и перезапусках служб.
- Синхронизация 3x-ui после успешного изменения срока/статуса больше не сообщает ложный отказ операции, если сам запрос к 3x-ui уже выполнен.
- Чтение status-файла после запуска update/rollback больше не способно превратить уже запущенную задачу в ошибочный HTTP-ответ.
- Ошибка записи локальной служебной таблицы после успешной операции теперь считается вторичной и отображается как предупреждение.
- Событие удаления пользователя записывается только после основной операции удаления, чтобы история не сообщала об удалении, которое фактически не состоялось.

## Изменено

- В веб-панели закреплён принцип: подтверждённый внешний side effect не должен превращаться в HTTP 500 из-за необязательной телеметрии, кэша, статуса или журнала.
- AJAX-отправка сообщения из «Сообщений» возвращает явный HTTP 200 + JSON при успешной доставке.

## Проверка

- Добавлены регрессионные тесты на post-success ошибки для панели и update workflow.
