# FargoVPN 5.0.1 — аудит и результаты проверок

Дата: 2026-10-08. Основа: предоставленный полный архив 5.0.0.

## Результат

Полный набор автоматических тестов: **142 passed**, без failed/skipped.
Из них 115 — существующие проверки проекта (с актуализированными ожиданиями версии и устаревшим DOM-стендом), 27 — новые поведенческие регрессии 5.0.1.

Архив предназначен для стандартного обновления 5.0.0 через панель. VERSION, app/VERSION и static/VERSION равны 5.0.1. Полная установка и автоматическое обновление используют прежний штатный установщик с исправлениями.

Это аудит предоставленного кода и тестирование в изолированной среде. Он не является подтверждением всех функций на production-сервере и не гарантирует отсутствие любых возможных ошибок.

## Найденные проблемы и исправления

| Область | Проблема | Исправление и проверка |
|---|---|---|
| Консольная установка | `read` читает pipe от `curl`, получает EOF и завершает меню | Для интерактивного запуска stdin переключается на `/dev/tty` до действий с системой. Псевдотерминал подтверждает ожидание и ввод `2`. Без терминала — понятная ошибка с кодом 2. `--update-existing` не требует TTY |
| Прерывание установки | Обработчик сигнала терял код ошибки после `echo` и мог завершиться успешно | Код передаётся явно. Проверены INT=130, TERM=143, HUP=129 и ошибка дочерней команды=7 |
| 3x-ui, сеть | В ответах с двумя сетевыми объектами накопленные байты и мгновенная скорость смешивались | `netTraffic` используется для итоговых байтов, `netIO` — для скорости, когда оба присутствуют. Для формата только со счётчиками поддержан расчёт разницы; сброс счётчика не даёт отрицательную скорость |
| 3x-ui, мониторинг | Карточка и узлы не обновлялись после открытия страницы; Fail2ban не запрашивался | Добавлен отдельный скрипт обновления карточки/узлов, запрос `fail2banStatus`, отображение ошибки. Независимые запросы локальных метрик, online и 3x-ui. Страница обновляется раз в 10 секунд, телеметрия 3x-ui кэшируется минимум 30 секунд |
| 3x-ui, совместимость | Некорректное число ломало снимок; строка `false` считалась true | Безопасные конечные числа и нормализация bool, включая состояния клиентов и узлов. Поддержан `panelVersion`. Проверены current/legacy формы клиентов, traffic/clientStats, netIO/netTraffic |
| 3x-ui, повторные операции | После таймаута POST мог уйти на другой URL и повторить уже применённое действие | POST не повторяется после сетевой ошибки/неоднозначного HTTP-сбоя. GET сохраняет ограниченные повторные попытки и fallback после 404 |
| 3x-ui, нагрузка | Один снимок дважды запрашивал inbound | Полученный список переиспользуется для трафика. Проверены кэш, онлайн, fallback clientStats и сохранение предыдущего снимка при недоступном API |
| Push, кнопки | Разрешение запрашивалось после сетевых ожиданий; после отключения использовалась старая подписка в памяти | `requestPermission()` вызывается до сетевой подготовки. После отключения сбрасывается контекст. Проверены включение → отключение → повторное включение, серверная ошибка и возврат кнопки в доступное состояние |
| Push, Service Worker | Ожидание активации могло зависнуть; удалялись кэши других приложений | Ограничено ожидание, удаляются только кэши FargoVPN; переходы из уведомлений ограничены origin и путём панели |
| Push, HTTP | Некорректный JSON/структура подписки приводили к необработанным ошибкам; общий выключатель обходился прямым POST | Проверка входных данных, запрет регистрации/теста при PUSH_ENABLED=False, блокирующие операции вынесены в threadpool. Проверены авторизация и CSRF |
| Push, ключи | Параллельная первая регистрация могла создать разные VAPID-ключи | Межпроцессная блокировка и атомарная запись приватного ключа с правами 0600. Проверены 16 параллельных инициализаций |
| Push, криптография | Требовалось проверить самостоятельную реализацию Web Push | Зашифрованное сообщение успешно расшифровано независимым HKDF/AES-GCM сценарием; подпись VAPID JWT проверена ECDSA. Ключи подписки валидируются до записи |
| Telegram-привязки | `logger` отсутствовал в обработчиках ошибки/отката | Добавлен logger; проверка неопределённых имён проходит |
| PostgreSQL-адаптер | Пустой executemany выполнял запрос; prefetched RETURNING-строка терялась в fetchall/fetchmany/итерации | Пустая партия не выполняет SQL. Первый результат сохраняется во всех способах чтения; поведенческие регрессии проходят |
| GitHub | Фильтр main пропускал резервные config, дополнительные .env, ключи и dump; shell-файлы теряли исполняемый режим | Усилен фильтр; `.env.example` остаётся доступным примером. `.sh` публикуются как 100755. Проверены состав main, текущие notes и атомарный commit с отказом при изменении ветки |
| Документация релиза | README/SECURITY содержали старые версии и несогласованные сведения | Обновлены версия, имя asset/tag, инструкция обновления и ссылка на этот отчёт |

## Остальные области покрытия

Существующие наборы тестов сохранены: регистрация по приглашению и ограничения попыток, Telegram ID и перенос привязок, состояние подписки, чеки и защита от дубликатов, медиа в переписке, журнал/прочтение сообщений, пагинация/сортировка пользователей, доставка рассылок, резервные копии/восстановление, диагностика, права publisher/follower, настройки, безопасные пути/архивы и обновления.

Часть этих проверок — контрактные проверки исходников, часть — поведенческие сценарии с SQLite-стендами или mock-объектами. Они не означают, что каждый маршрут бота и каждое действие панели выполнены на реальном Telegram/3x-ui/PostgreSQL.

Из исходных тестов один падал из-за устаревшей DOM-заглушки (не поддерживала replaceChildren и ожидала удалённый фильтр дат). Заглушка обновлена с проверкой реального порядка строк; assertions функциональности сохранены. Ожидания текущей версии в release-тестах обновлены на 5.0.1; исторические секции CHANGELOG сохранены.

## Ограничения и проверка после обновления

Не выполнялись: реальная установка/откат на Ubuntu/Debian с systemd, миграции на живом PostgreSQL, реальный 3x-ui API, отправка Telegram-сообщений/чеков/OCR на сервере, доставка через Mozilla/FCM/Apple на устройство и создание реального GitHub Release.

Живое содержимое GitHub-репозитория не удалось прочитать из этой среды. Проверено оформление предоставленного проекта и код публикации, а не состояние уже опубликованной удалённой ветки. Токены/сервер пользователя не использовались, публикация не выполнялась. Исправленный публичный `curl | bash` станет доступен из GitHub после публикации нового полного пакета штатной главной панелью.

После установки 5.0.1:

1. Дождаться итогового health-check и открыть новую страницу панели.
2. В мониторинге сравнить online/трафик/скорость с 3x-ui; проверить изменение карточки и узлов после одного периода кэша. Старые 3x-ui могут не поддерживать nodes/Fail2ban: отсутствие дополнительных данных не объявляется аварией Xray.
3. В настройках уведомлений выполнить «Включить», «Тест», «Выключить», снова «Включить»; подтвердить системное уведомление на устройстве. Для iOS открыть установленную PWA.
4. Проверить пользователей, регистрацию, тестовую оплату, переписку, резервную копию и одну рассылку на тестового получателя.
5. При публикации на GitHub сверить tag FargoVPN-5.0.1, asset, SHA-256 и обновление main. Если публикация не нужна, локальное обновление панели её не требует.

Автоматические проверки не заменяют эту проверку реальных интеграций.
