## 5.1.5

### Исправлено
- Исправлен запуск фонового обновления из веб-панели: worker запускается через отдельную systemd-задачу с проверкой фактического старта.
- Добавлен launcher-log, поэтому ошибки до запуска Python worker больше не теряются.
- Исправлен сценарий, при котором статус обновления мог оставаться на 2% без журнала.
- CI синхронизирован с минимальной структурой репозитория и зависимостями из app/requirements.txt.
- Обновление и публикация GitHub используют единый release tree.

## 5.1.4

- Живой прогресс установки в веб-панели теперь отображается по этапам и продолжает анимироваться во время долгих операций.
- После завершения обновления страница «Обновления» автоматически открывается на новой версии после восстановления веб-службы.
- Публикация GitHub переведена в отдельный фоновый процесс с постоянным прогрессом `main → release → assets → verification`, видимым из панели.
- Исправлено восстановление отслеживания задачи обновления после перезапуска веб-службы.

# Changelog

## 5.1.3

### Added
- Новая компактная структура публичного репозитория: runtime находится в `app/`, документация — в `docs/`, проверки — в `tests/`, а корень содержит только публичный bootstrap, README и LICENSE.
- Строгая проверка структуры репозитория в CI.
- Публикация `main` из панели теперь синхронизирует точное дерево архива без искусственного корневого `VERSION`.

### Changed
- Полный установщик перемещён в `app/install.sh`; корневой `install.sh` является только bootstrap.
- Release tags используют формат `vX.Y.Z`.
- Обновление из панели использует `app/install.sh` внутри release-пакета.

### Fixed
- Исправлены синтаксические ошибки Python 3.10/3.11 в Push и веб-навигации.
- Исправлены устаревшие CI-тестовые контракты.
- Прогресс фонового обновления использует реальный статус задачи.

## 5.1.2

Исправления очистки `main` и отображения прогресса обновления.
