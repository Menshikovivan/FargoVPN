## 3. Ограничения среды

Три существующих HTTP/бот-теста не могут импортировать код до начала сценария, потому что в рабочем окружении нет пакетов `psycopg` и `aiogram`. Эти зависимости объявлены в `requirements.txt`; установить их автоматически из сети в этой среде не удалось.

Не выполнялся реальный системный install/update на Ubuntu/Debian с systemd, не выполнялся реальный restart служб, не проверялся живой 3x-ui API и не публиковался GitHub Release. Поэтому эти части требуют ручной проверки на реальном сервере.

## 4. Главные регрессии 5.0.0

- Рассылка из панели не должна показывать пользователю JSON-ответ `202`: обработчик перенесён в `static/panel.js`, использует `preventDefault()` и `stopImmediatePropagation()`, показывает прогресс/ошибки и блокирует повторную отправку.
- Пользователи: фильтрация имеет серверный fallback, диапазон дат регистрации убран из интерфейса, добавлена сортировка «По дате регистрации» с направлением «По возрастанию / По убыванию».
- Диагностика: runtime-проверки базы переведены на PostgreSQL; SQLite PRAGMA/quick_check из `diagnostics.py` удалены.
- Установщик: свободное место проверяется на реальном целевом разделе и разделе бэкапов; временный каталог проверяется мягко; bootstrap выбирает доступный временный раздел и проверяет SHA-256.
- Профиль облегчённого профиля удалён как пользовательская опция и из релизных файлов; старый `INSTALL_PROFILE` читается только при обновлении старых установок для безопасной совместимости.
- GitHub Release: описание содержит только текущую секцию CHANGELOG, стандартную команду установки и инструкцию обновления; asset-имена нормализованы.
- Bootstrap не использует `exec` для запуска штатного installer, чтобы `EXIT`-trap гарантированно удалял временные файлы.

## 5. Безопасность релиза

Перед упаковкой должны быть удалены `__pycache__` и `.pytest_cache`. В финальный архив не включаются `.git`, боевые `config.py`, `.env`, базы данных и логи. `config.example.py` содержит только примерные/пустые секреты.

## Регрессия обновления 4.x → 5.0.0 — 2026-10-08
- Причина: старый `update_manager.py` из 4.x передавал установщику `--profile <значение>`, тогда как штатный `install.sh` 5.0.0 параметр уже не принимал.
- Исправление: `install.sh` 5.0.0 принимает legacy-аргумент `--profile` / `--profile=...` только как параметр совместимости и принудительно использует полный профиль.
- Это позволяет установить первый 5.0.0 поверх старой панели; после перехода на 5.0 новый `update_manager.py` больше не передаёт `--profile`.
