# Установка и обновление FargoVPN 5.1.21

Используйте FargoVPN-5.1.21_FULL.tar.gz; предыдущий 5.1.21-audit.1 заменен этой сборкой. Базовый Nginx L4/3x-ui должен быть установлен заранее. Новый FargoVPN не устанавливает и не заменяет его.

## Перед обновлением

Сохраните независимые копии установленного каталога FargoVPN, его config.py и согласованный pg_dump его PostgreSQL. Сохраните также базу/конфигурацию3x-ui штатным способом. Храните хотя бы одну копию вне обновляемого каталога/сервера. Проверьте свободное место: новый auto-backup включает .venv, дамп БД и файлы.

Проверьте nginx -t и что существующая панель работает. Не запускайте одновременно backup/restore/другой updater. Остановите сторонние приложения, которые пишут в ту же PostgreSQL БД FargoVPN. Автооткат управляет только службами приложения и его public schema.

Перенесите на сервер архив и SHA256SUMS-5.1.21.txt. В каталоге с архивом проверьте его сумму:

```bash
sha256sum --ignore-missing -c SHA256SUMS-5.1.21.txt
```

Проверка должна показать FargoVPN-5.1.21_FULL.tar.gz: OK. Перед запуском используйте отдельный каталог распаковки, а не установленный каталог приложения.

## Обновление стандартной установки

Команды ниже предполагают установленное приложение в /root/vpn_bot и выполнение от root:

```bash
tar -xzf FargoVPN-5.1.21_FULL.tar.gz
cd FargoVPN-5.1.21
bash ./install.sh --update-existing /root/vpn_bot
```

Если приложение находится в другом месте, укажите фактический путь вместо /root/vpn_bot. Установщик использует локальный пакет; скачивание GitHub latest для этого не требуется. Не используйте FARGOVPN_USE_REMOTE_LATEST=1: оно переключает bootstrap на внешнюю latest-версию.

## Новая установка поверх готового Nginx L4/3x-ui

```bash
tar -xzf FargoVPN-5.1.21_FULL.tar.gz
cd FargoVPN-5.1.21
bash ./install.sh
```

Выберите «Новая установка» и задайте собственные реквизиты. Telegram/3x-ui/API можно заполнить в настройках; без них соответствующие функции не работают. Если обнаружены чужие DB/role, bootstrap создает отдельные, не меняя старый пароль.

## После установки

Повторно войдите в панель: старые cookies больше не подходят. Сверьте версию5.1.21, доступность своей панели и3x-ui через прежние URL, диагностику и настройки интеграций. Проверьте:

```bash
nginx -t
systemctl is-active vpn-service-web.socket vpn-service-web.service nginx
systemctl status vpn-service-bot.service --no-pager
```

Бот без BOT_TOKEN штатно не запускается. Проверяйте его после настройки настоящего токена; статус web200 не подтверждает Telegram или VPN. Проверьте одну тестовую подписку на собственном клиенте, отправку сообщения и доступ через внешнюю сеть.

Полный журнал установщика: /var/log/vpn-service-install.log. При ненулевом завершении прочитайте сообщение rollback и статус БД/служб перед повторным запуском; не удаляйте pre_update копии.

## Важное отличие restore5.1.21

Backup импортирует данные и разрешенные бизнес-настройки в текущую доверенную схему. Архивный SQL/код, systemd, .env, ключи и настройки запуска не устанавливаются. Тип БД3x-ui должен совпадать; несовместимая схема/FK отвергаются. Для старой версии сначала отдельно установите ее доверенный пакет. Не используйте backup как способ перенести исполняемые файлы с неизвестного сервера.

Проверенная конфигурация и точные границы приведены в AUDIT_REPORT_FINAL.md. Этот пакет прошел реальную Linux-приемку; настройки и внешние учетные данные вашего конкретного сервера не проверялись удаленно.
