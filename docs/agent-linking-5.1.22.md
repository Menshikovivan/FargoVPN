# Агент: несколько Telegram аккаунтов

Задача: проверить существующую модель идентичности и предложить привязку дополнительных Telegram аккаунтов к одному VPN профилю без слияния чужих подписок.

Проверены `users`, `payments`, cabinet token resolution, `identity_migration.py`, существующие bind URL и обработчики `/start`. Один Telegram ID сейчас является ключом VPN клиента, платежей, кабинета и истории. Существующая привязка переносит/заменяет ID, поэтому её нельзя переиспользовать для семейного членства.

Рекомендована отдельная таблица связи: уникальный дополнительный Telegram ID, основной профиль, запрет циклов/самопривязки, отдельное подтверждение аккаунта, сохранение исходной строки пользователя. Участника с собственным VPN профилем нельзя автоматически переносить.

Реализация: миграция создаёт self-link для существующих записей, семейная ссылка действует 30 минут, хранится только SHA-256, потребляется одноразово после открытия ботом. Оба аккаунта должны пройти PIN; конфликтующий аккаунт с UUID/email/sub_id/сроком отклоняется. Кабинет и расчёт оплаты дополнительного ID резолвятся к основному профилю. PostgreSQL smoke проверил связь и запрет потери профиля.
