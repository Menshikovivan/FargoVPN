# Отчёт агента: приглашения существующих Telegram-пользователей

## Область

Проверены семейный `/start family_<token>`, глобальный PIN middleware, создание пользователя при первом сообщении, одноразовое принятие приглашения и валидация существующих VPN-данных. Работа ограничена файлами `app/telegram_registration_middleware.py`, `app/services/billing.py` и `tests/test_family_invitation_gate.py`.

## Что изменено

- Семейный deep-link теперь пропускается до ограничения повторных PIN-попыток. Пользователь, уже известный боту и временно заблокированный от ввода PIN, может принять приглашение. Это не снимает PIN-блокировку и не даёт доступ к другим функциям: профиль остаётся в `awaiting_invite`, пока PIN не будет проверен.
- Для существующих строк пользователя с остаточным `expiry_time`, но без UUID, email или subscription ID, срок истечения больше не считается самостоятельным VPN-профилем. Такие записи теперь можно привязать к семейному профилю; реальные идентификаторы отдельной подписки по-прежнему запрещают привязку, чтобы не объединять два действующих профиля автоматически.
- Сохранены короткоживущий хешированный токен, проверка PIN владельца, запрет самопривязки, лимит четырёх записей с владельцем и запрет повторного/просроченного токена. Pending-участник сохраняет свой PIN-статус после привязки.
- Повторное открытие нового действующего приглашения тем же участником теперь проверяет существующую связь до лимита. Если участник уже привязан именно к этому владельцу, запрос завершается идемпотентно и новый токен помечается использованным даже при заполненном профиле. Если связь принадлежит другому владельцу, запрос отклоняется, токен остаётся неиспользованным. При новой привязке сохраняется обработка гонки через уникальную связь и проверка владельца до расходования токена.

## Проверки

Команда `pytest tests/test_family_invitation_gate.py tests/test_billing_status.py -q` — **9 passed**. Добавлен поведенческий тест с заполненным профилем: повторное приглашение своего участника успешно расходует токен без проверки лимита, связь с другим владельцем отклоняется и токен не расходуется.

Попытка дополнительно запустить `tests/test_registration_access.py` не завершилась нормальным отчётом pytest в доступное время: процесс оставался на ошибках фикстуры/окружения (`EEEEEEEEEE`). Она не относится к изменённым маршрутам; успешные целевые проверки семейного приглашения выполнены отдельно.

## Ограничения

Telegram API и production-бот не подключались. Принятие приглашения и обновление billing/рассылок на реальном сервере требуют интеграционного теста после выкладки; миграции и схема БД в рамках этой подзадачи не менялись.
