# FargoVPN 5.1.12 — QA report

Дата прогона: 2026-10-09.

## Первопричины четырёх исходных ошибок

Общий корень — две разные CSP-политики в одном ответе: приложение разрешало inline/page-specific JavaScript, а внешний Nginx добавлял более строгую `script-src 'self'`. Браузер применял обе политики, поэтому inline-обработчики вкладок/форм не запускались. После их отказа глобальный submit-helper `panel.js` перехватывал POST-формы и для успешного/redirect-ответа делал `location.assign`, что объясняет переход после отправки сообщения и проверки GitHub. Кнопка публикации была `type=button` и зависела только от своего inline click-handler, поэтому при заблокированном inline JS она вообще не инициировала запрос. Журналы также зависели от page-specific JS для `change`/`click`, поэтому выбор фильтра визуально не приводил ни к какому запросу.

### Ключевые регрессионные сценарии

1. Отправка сообщения: `preventDefault` → JSON/AJAX → новое событие сразу добавляется в чат → форма очищается → focus возвращается в textarea; при ошибке payload сохраняется и появляется «Повторить».
2. Входящее сообщение: polling `/api/panel/messages/feed` не перезагружает страницу, сохраняет позицию чата; unread summary обновляется.
3. Журналы: запросы выполняются асинхронно, выбираются `app/bot/web/update/github-publish/github-launcher/push/backup/backup-live/reminders`, читается только хвост файла.
4. GitHub auth: GET `/user`, GET repository, проверка permissions и target branch; 401/403/404 отображаются отдельно; токен не возвращается и не логируется.
5. GitHub publish: запуск защищён от двойного старта; состояние хранится на сервере; status/log/history восстанавливаются после reload; после публикации заново подтверждаются Release, tag и target branch commit SHA.

## Ограничения среды

Невозможно было поднять настоящий PostgreSQL сервер: в контейнере отсутствуют `postgres`, `psql`, `initdb`; сетевой `pip install` не работает из-за отсутствия DNS/интернета. Поэтому PostgreSQL seeder подготовлен и проверен статически, но реальный запуск на сотнях записей выполнится командой `FARGOVPN_DATABASE_URL=... tests/qa/seed_test_db.py` на отдельной QA-БД.
