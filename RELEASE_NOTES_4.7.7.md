# FargoVPN 4.7.7

## Исправлено

- Вкладка «Сообщения» получила инкрементальное автообновление без перезагрузки страницы: журнал читается по `user_events.id`, подтягиваются только новые события, изменившиеся диалоги и актуальный unread-счётчик.
- Новые сообщения в открытом диалоге добавляются в конец без перерендера страницы. Если оператор прокрутил историю вверх, позиция скролла сохраняется.
- Добавлена отправка сообщения прямо из вкладки «Сообщения». Используется существующий endpoint `/users/{tg_id}/message`, поэтому логика Telegram API, журналирования и обработки ошибок не дублируется.
- Для composer добавлены `Enter` = отправить и `Shift+Enter` = новая строка; на мобильном поле и кнопка адаптированы под узкий экран.
- Успешно отправленное сообщение сразу добавляется в открытую переписку из точной записи журнала, без гонки между несколькими администраторами.
- В истории по-прежнему отображаются исходящие сообщения панели (`direction=out`) и служебные сообщения бота (`message_kind=service`); динамическая вставка использует `textContent` для защиты от XSS.
- Частые Telegram ошибки для оператора преобразуются в понятные уведомления: «диалог не начат», «бот заблокирован», «чат не найден», rate limit и сетевой timeout.

## Технические изменения

- Добавлены `user_events.recent_all_events()` и `conversation_users_for_ids()` для дешёвого polling по индексированному `user_events.id` без полной выборки истории.
- Новый feed API защищён тем же `require_auth`, что и остальные API панели.
- При большой пачке событий feed не перескакивает через историю: курсор продвигается до реально возвращённого последнего `id` и продолжает догонять следующими запросами.
- Новых таблиц и миграций БД нет.

## Проверка

- Полный регрессионный набор FargoVPN: 75/75 тестов.
- Дополнительные тесты 4.7.7: live feed cursor, dialog updates, отправка из Messages, Enter/Shift+Enter, XSS-safe DOM insertion и friendly Telegram errors.
