Готовая платформа для продажи и сопровождения VPN‑подписок «под ключ»: Telegram‑бот для клиентов, веб‑панель администратора, интеграция с 3x‑ui, приём платежей с автоматической проверкой чеков (OCR), резервное копирование, массовые рассылки и самообновление через GitHub Releases.
Платформа разворачивается на собственный VPS одной командой (`install_with_web.sh`) и рассчитана на тех, кто продаёт доступ к VPN небольшой аудитории и хочет автоматизировать выдачу подписок, приём оплаты и поддержку клиентов через Telegram — без стороннего SaaS и без передачи данных клиентов третьим сервисам.

Возможности
🤖 Telegram‑бот для клиентов
Inline‑меню (без устаревшей `ReplyKeyboardMarkup`): «Моя подписка», «Купить/продлить VPN», FAQ, связь с администратором.
Инструкции по подключению для Incy и HApp, раздел «если VPN не подключается».
Приём чека об оплате прямо в чате, статус подписки и остаток трафика.
Идентификация пользователя строго по Telegram ID — `@username` не используется как ключ, так как может измениться.
🛠 Админ‑панель в Telegram
Управление пользователями, ручная выдача доступа, подтверждение/отклонение платежей — без выхода из чата.
Синхронизация с 3x‑ui и запуск массовой рассылки прямо из диалога с ботом.
🖥 Веб‑панель администратора
Пользователи — список, карточка, создание, продление, привязка Telegram, блокировка, удаление, импорт из старой базы с превью перед применением.
Платежи — очередь чеков, просмотр присланного изображения, подтверждение/отклонение.
Рассылки — массовая отправка сообщений и медиа по базе подписчиков в фоне.
Мониторинг и диагностика — состояние базы, хранилища, трафика, уведомлений и обновлений; перезапуск сервисов.
Резервные копии — создание, скачивание, восстановление и удаление архивов прямо из панели.
Логи — просмотр журналов systemd‑сервисов без выхода в консоль.
Настройки — параметры сервиса, оплаты, OCR‑проверки чеков, Яндекс.Диска и обновлений.
Встроенный чат с историей переписки и непрочитанными сообщениями — общий журнал для бота и панели.
💳 Приём оплаты и проверка чеков (OCR)
Локальное распознавание банковских квитанций (`pytesseract`, рус/eng) — без передачи изображений во внешние сервисы.
Настраиваемые правила автоподтверждения: сумма, получатель (с алиасами), статус операции, срок давности чека, защита от повторной отправки одного и того же чека.
OCR — вспомогательная эвристика: сомнительные платежи остаются в очереди на ручную проверку, а не подтверждаются автоматически «на глаз».
🔌 Интеграция с 3x‑ui
Трафик, срок действия и last‑online считаются авторитетными данными 3x‑ui; локальная SQLite‑база бота — только кэш и метаданные.
Периодическая синхронизация клиентов между ботом и панелью 3x‑ui.
💾 Резервное копирование
Локальные архивы + доставка в Telegram (по частям), на Яндекс.Диск (OAuth REST API или локальный WebDAV‑диск) и через `rclone` как legacy‑способ.
Расписание по интервалу, автоочистка старых копий, повторные попытки при сбое доставки, восстановление прямо из панели.
🔄 Самообновление и откат
Единственный источник обновлений — GitHub Releases: панель проверяет последний опубликованный релиз репозитория, скачивает архив и валидирует его SHA‑256, размер, версию, структуру и защиту от path traversal перед установкой.
Публикация релиза доступна прямо из веб‑панели для выделенного администратора‑издателя.
Перед обновлением создаётся проверенная резервная копия — при ошибке выполняется автоматический откат.
🔐 Безопасность
CSP, HSTS (при HTTPS), `X-Content-Type-Options`, `X-Frame-Options`, Referrer/Permissions Policy, отклонение межсайтовых изменяющих запросов.
Ограничение попыток входа по IP и логину с нарастающей экспоненциальной блокировкой (хранится в SQLite).
Constant‑time сравнение секретов — логин и пароль веб‑панели поддерживают кириллицу и Unicode без утечки по времени ответа.
Пароль хранится как `pbkdf2_sha256` с уникальной солью; ключ сессии генерируется установщиком случайным образом.
Медиафайлы переписки отдаются только через авторизованный маршрут с проверкой владельца события; бинарные данные не хранятся в SQLite.
Подробная модель угроз — в `SECURITY.md`.

Требования

Telegram Bot Token.
Python 3.10+ (разворачивается установщиком в отдельном виртуальном окружении, зависимости ставятся автоматически).
Установка
Новая установка
```bash
cd /root
tar -xzf VPN_Service_Platform_3.0.9_FULL.tar.gz
cd VPN_Service_Platform_3.0.9_FULL
sudo bash install_with_web.sh
```
Установщик запросит параметры бота, панели и сервиса, создаст рабочий каталог `/root/vpn_bot`, виртуальное окружение и systemd‑сервисы `vpn-service-bot` и `vpn-service-web`.
Только бот (без веб‑панели)
```bash
sudo bash install_bot_only.sh
```
Облегчённый профиль — без FastAPI/Uvicorn и веб‑зависимостей (`app/requirements-lite.txt`), подходит, если панель не нужна.
Обновление существующей установки
```bash
sudo bash install_with_web.sh --update-existing /root/vpn_bot
```
При обновлении сохраняются `config.py`, база данных, пользователи, платежи, настройки обновлений и текущее виртуальное окружение. Обновления также можно публиковать и накатывать прямо из веб‑панели (см. «Самообновление и откат» выше).
Проверка после установки
```bash
curl -fsS http://127.0.0.1:8088/health
sudo systemctl status vpn-service-bot vpn-service-web --no-pager
sudo journalctl -u vpn-service-web -n 100 --no-pager
```
Ожидаемая версия эндпоинта `/health`: `3.0.9`.

Безопасность
Подробная модель угроз, рекомендации по хранению секретов, настройке reverse proxy и защите обновлений — в `SECURITY.md`. Кратко:
Файл `config.py` должен иметь права `600` — в нём хранятся Bot Token, API‑токен 3x‑ui, хеш пароля панели, ключ сессий и платёжные реквизиты.
Веб‑панель рекомендуется публиковать только через HTTPS reverse proxy или ограничивать доступ firewall/VPN‑сетью.
Подпись обновлений отдельным асимметричным ключом не реализована: целостность архива обновления обеспечивается SHA‑256 поверх доверенного HTTPS‑канала и секретного токена — публикуйте только самостоятельно проверенные релизы.
Если вы обнаружили уязвимость — пожалуйста, не создавайте публичный issue; свяжитесь с автором репозитория напрямую.
